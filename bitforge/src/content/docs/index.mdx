	<h1>Reproducible Yocto builds, one binary</h1>
	<p class="lede">
		<code>BitForge</code> scaffolds a Yocto workspace, manages poky /
		OpenEmbedded layers declaratively in <code>BitForge.toml</code>, pins every
		layer in a lockfile, generates your BitBake config, and serves a live web
		UI to launch and watch builds.
	</p>

<section>
	<h2>Features</h2>
	<div class="oss-grid">
		<article class="oss-card">
			<h3>One-command bootstrap</h3>
			<p>
				<code>bitforge --init</code> clones poky or OpenEmbedded-core plus
				BitBake, scaffolds a starter layer and writes a working config.
			</p>
		</article>
		<article class="oss-card">
			<h3>Declarative layers</h3>
			<p>
				Add and remove upstream layers with one command; the manifest and
				<code>bblayers.conf</code> stay in sync automatically.
			</p>
		</article>
		<article class="oss-card">
			<h3>Locked &amp; reproducible</h3>
			<p>
				Every dependency is pinned to an exact commit in
				<code>BitForge.lock</code>, so a checkout rebuilds the same tree.
			</p>
		</article>
		<article class="oss-card">
			<h3>Live build web UI</h3>
			<p>
				A built-in server streams BitBake output in real time — start builds
				from the CLI or the browser.
			</p>
		</article>
		<article class="oss-card">
			<h3>Single static binary</h3>
			<p>
				No Python venv or global installs to manage — download one binary
				with the install script and run it.
			</p>
		</article>
		<article class="oss-card">
			<h3>Self-updating</h3>
			<p>
				<code>bitforge --update</code> fetches the latest release, with a
				<code>--beta</code> channel for early builds.
			</p>
		</article>
	</div>
</section>
