<section>
	<h2>Features</h2>
	<div class="oss-grid">
		<article class="oss-card">
			<h3>Faster UI/UX development</h3>
			<p>
				Open your app in a real browser and attach modern devtools,
				responsive emulation and design tooling while the native backend
				keeps running.
			</p>
		</article>
		<article class="oss-card">
			<h3>Browser-based E2E testing</h3>
			<p>
				Point Playwright, Cypress or any web testing tool at the remote URL
				to exercise your real app without modifying it.
			</p>
		</article>
		<article class="oss-card">
			<h3>Transparent IPC bridge</h3>
			<p>
				<code>invoke</code> and <code>listen</code> automatically fall back
				to a WebSocket transport when running outside the webview — your
				frontend code stays the same.
			</p>
		</article>
		<article class="oss-card">
			<h3>Network access control</h3>
			<p>
				Bind to localhost, your local subnet, or anywhere — with per-peer
				address filtering and a localhost-only default.
			</p>
		</article>
		<article class="oss-card">
			<h3>Latency tracking</h3>
			<p>
				A built-in ping/pong heartbeat surfaces live round-trip latency to
				your frontend so you can monitor connection quality.
			</p>
		</article>
		<article class="oss-card">
			<h3>Drop-in npm package</h3>
			<p>
				Swap <code>@tauri-apps/api</code> imports for
				<code>tauri-remote-ui/api/*</code> and you are ready for both desktop
				and remote sessions.
			</p>
		</article>
	</div>
</section>

<section>

	<div class="oss-grid">
		<article class="oss-card">

			<p>

				modifying app logic.

		</article>

				another device on the network.
			</p>
		</article>
	</div>
</section>

	<Aside type="danger" title="Read this before exposing the server">
	The plugin currently has **no authentication, authorization or TLS**. Anyone who
	can reach the bound port can invoke any command your app exposes. Keep the
	default localhost scope, or place the server behind your own auth/TLS layer.
	See [Security](/tauri-remote-ui/security/) for the full model.
	</Aside>
