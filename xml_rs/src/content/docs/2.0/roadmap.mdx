The v2.x line builds on the stable, round-trip-safe DOM from v1.x. Its headline
goal is **native XPath querying**, plus supporting ergonomics for selecting and
extracting data from a parsed tree.

## Headline: XPath support <Badge text="Planned" variant="caution" />

Today you navigate the tree with structural helpers such as
[`find_first_child`](/xml_rs/2.0/guides/navigating/#find-children),
`get_elements_by_tag_name` and `find_first_by_attribute`. v2 aims to add a
single expression-based entry point so you can locate nodes with familiar XPath
syntax instead of chaining calls.

The target API is a `query_xpath` method on
[`XmlDocument`](/xml_rs/2.0/api-reference/#xmldocument):

```rust
// Target API — not yet available.
let titles = document.query_xpath("//book[@id='bk101']/title")?;
for node_id in titles {
    let title = document.get_element(node_id)?;
    println!("{}", title.get_text_content());
}
```

### Design goals

- **Zero-copy over the existing DOM** — XPath evaluation returns
  [`NodeId`](/xml_rs/2.0/api-reference/#types) values into the current tree, with
  no separate document model.
- **Namespace-aware** — expressions resolve prefixes through the same
  [`NamespaceDeclaration`](/xml_rs/2.0/api-reference/#namespacedeclaration)
  scope used elsewhere, keeping results round-trip-safe.
- **No `unsafe`** — consistent with the rest of the crate.
- **Incremental** — child/descendant axes and attribute predicates ship first;
  richer axes and functions follow.
